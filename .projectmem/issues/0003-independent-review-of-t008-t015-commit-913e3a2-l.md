# #0003 Independent review of T008-T015 (commit 913e3a2, local tracker integration layer) found a BLOCKING crash-safety gap: Local.Store.decode_store/1 (local/store.ex) validates only that the top-level JSON has format_version:1 and issues is a map -- it never validates that each issue record VALUE is itself a map. A hand-edited local_tracker.json with a malformed record (e.g. "ISSUE-1": "todo" instead of an object) passes validate_config/1 at startup (top-level shape only) but crashes Local.Adapter.to_issue/1 (adapter.ex:80, Map.get on a non-map) with BadMapError on the first fetch_issues_by_states/fetch_issues_by_ids call. This exception is unhandled all the way up through Orchestrator.handle_info(:run_poll_cycle) (orchestrator.ex, maybe_dispatch/reconcile_running_issues/reconcile_blocked_issues have no try/rescue), crashing the Orchestrator GenServer. AgentRuntimeSupervisor supervises Orchestrator and Task.Supervisor under strategy: :one_for_all (agent_runtime_supervisor.ex:32), so the crash kills Task.Supervisor too -- terminating every in-flight coding-agent Task across all issues. This directly violates FR-008.3's 'leave already-running attempts undisturbed' guarantee. Reproduced via a scratch ExUnit test (not committed) seeding a Local.Store-backed data file with a non-map issue record and calling Local.Adapter.fetch_issues_by_ids/1 directly -- confirmed BadMapError at lib/symphony_elixir/local/adapter.ex:80.
